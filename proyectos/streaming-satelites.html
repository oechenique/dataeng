Streaming de satélites en tiempo real — Databricks

Posiciones orbitales calculadas localmente con el algoritmo SGP4 a partir de TLEs, publicadas a Azure Event Hubs y procesadas con Spark Structured Streaming en un Lakeflow Pipeline serverless (Bronze → Silver → Gold), servidas en un AI/BI Dashboard nativo con refresh en vivo. Tercer proyecto de la serie, después del pipeline batch y el agente conversacional: cierra el combo con streaming real.

Productor local (SGP4 sobre TLEs) → Azure Event Hubs (endpoint Kafka) → Lakeflow Pipeline serverless en Databricks con Structured Streaming: Bronze (crudo) → Silver (dedupe + tipado) → Gold (agregaciones en ventana) → AI/BI Dashboard nativo leyendo de Gold, con "Embed data" desactivado para que cada refresh traiga datos nuevos en vivo. Infra completa en Azure (Event Hubs, Databricks Premium, Key Vault) desplegada con Terraform.

Decisiones de ingeniería
  • SGP4 corrido localmente como productor de eventos — una fuente real y sin rate limit para probar backpressure y ventaneo, no un mock.
  • Azure Event Hubs como broker compatible con Kafka — desacopla el productor del consumer de Structured Streaming, misma forma que un streaming real en producción.
  • Dedupe y tipado aislados en Silver — mantiene las agregaciones de Gold limpias aunque el productor emita posiciones superpuestas.
  • AI/BI Dashboard con "Embed data" apagado — sirve resultados en vivo sin construir un frontend aparte.

El problema
Un pipeline de streaming necesita un productor de eventos real para probar backpressure, ventaneo y agregaciones tal como se comportan en producción — no un mock ni algo atado a los rate limits de una API externa.
La solución
Los TLE orbitales cambian poco, pero la posición exacta en cualquier instante se calcula con SGP4 — corrido localmente cada pocos segundos, ese cálculo es el productor de eventos real del proyecto. Misma arquitectura que cualquier streaming real: productor → broker → consumer incremental → agregaciones en ventana.
