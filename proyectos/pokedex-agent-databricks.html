Pokedex Agent — Agente Claude con MCP en Databricks

Plataforma de datos Pokémon en Databricks (Terraform + Medallion) con un agente Claude ("Profesor Oak") que consume la capa Gold vía Model Context Protocol — cada ficha, comparación y matchup sale de un pipeline curado, sin que el modelo invente un solo stat. Quinto proyecto de la serie, y el primero que expone datos a un agente LLM a través de tools propias con hooks reales.

5 fuentes de PokeAPI se ingestan en paralelo hacia Bronze, se normalizan y tipan en Silver, y pasan por un Data Quality gate antes de llegar a Gold (pokemon_profile, battle_stats, type_matchups, generation_summary) — si el gate falla, el pipeline se detiene y Gold no se actualiza. Un MCP server desplegado como Databricks App expone esa capa Gold con 4 tools de solo lectura, y el agente Claude "Profesor Oak" las consume con hooks propios antes de responder en oak_app, una segunda Databricks App en Streamlit con tema Día/Noche.

Decisiones de ingeniería
  • Todo cálculo (totales, ratios de batalla, matchups de tipo) se hace en el pipeline Gold, nunca en el prompt — el agente lee un resultado ya calculado, no infiere efectividad de tipos por su cuenta.
  • Null explícito en vez de inventar — si un Pokémon no tiene carta TCG o precio de mercado, pokemon_card_summary devuelve null y el agente lo reporta tal cual, nunca estima un valor plausible.
  • 5 tools del MCP server granulares en vez de una gigante, con schema estricto y enums para type/generation — nunca texto libre.
  • Hooks reales, no solo logging: PreToolUse valida el Pokémon y la generación contra Gold antes de ejecutar la tool; PostToolUse detecta isError: true para que el agente reporte el fallo en vez de tratarlo como dato válido.
  • Pivot de un frontend Next.js/Vercel a una segunda Databricks App en Streamlit (oak_app) tras un 401 intermitente en la propagación de permisos de un service principal M2M — resuelto con auth app-to-app nativa en vez de M2M externo.

El problema
Exponer una capa de datos curada a un agente LLM sin que ese agente termine inventando stats, matchups o precios — y sin mezclar la personalidad del agente con las reglas operativas que tiene que cumplir sí o sí.
La solución
Pipeline Medallion con Data Quality gate real entre Silver y Gold, un MCP server de solo lectura con tools granulares y schemas estrictos, y un agente Claude ("Profesor Oak") con hooks que validan el input antes de ejecutar cada tool y detectan errores en el resultado — la personalidad vive en el system prompt, separada por completo de las reglas operativas.
